## Current Problem: example-wind-tunnel

New files were added under `examples/example-wind-tunnel/`.

The example compiles, but the visual is not acceptable yet.

Observed problems from user screenshots:

- First version had obvious triangular/repeated bands because the inlet used repeated circular splats.
- Second version had worse time-slice stripes because many small density splats were advected by a stable velocity field.
- Third version used continuous density/velocity textures, but it became a wide cyan band; obstacles only cut dark channels through it.
- Latest version narrowed the source and changed raw density texture blending, but still shows periodic vertical bands/time-slice artifacts and does not look like a proper wind tunnel.

Do not continue blindly tuning strength/decay. The likely root causes are structural:

- The current obstacle implementation clears velocity/density/temperature after injection/advection, but does not fully participate in divergence, pressure Jacobi, gradient subtraction, vorticity, or neighbor boundary handling.
- PixelFlow/ofxFlowTools obstacles are used as solver boundary textures, often with obstacle-offset neighbor masks. Our current mask is useful but incomplete for convincing wake behavior.
- The source model is still too synthetic. A steady inlet plus fixed timestep turns source updates into visible temporal slices.
- Current raw density texture blending has been changed to alpha-based mix for non-velocity textures, which needs visual regression against `camera-fluid`, `simple`, and any future bridge texture examples.
